===============================================================================
 KOZMOK CRM  -  MANUAL DE USUARIO
 Tienda de electronica / computo con tienda en linea, CRM y chatbot.
 Ultima actualizacion: septiembre 2026
===============================================================================

Este documento explica, seccion por seccion, que hace cada parte del sistema
para estos perfiles:

   - CLIENTE   : la persona que compra en la tienda en linea.
   - ADMIN     : administrador del negocio, acceso total al panel.
   - VENDEDOR / SOPORTE / ALMACEN : personal interno con un menu recortado
                 segun su rol (ver seccion 5).

Si eres un admin nuevo, lee las secciones 1, 2, 4 y 6. El resto sirve de
consulta.


===============================================================================
 1. ARRANQUE DEL SISTEMA (para quien instala o levanta el proyecto)
===============================================================================

Requisitos
   - Node.js 18 o superior.
   - PostgreSQL 16 o superior (se probo con 18).

Configuracion de la base
   - El archivo  tiendatech/db.config.js  tiene usuario, host, base, password
     y puerto. Ajustalo a tu instalacion local. Por defecto:
        user: postgres   host: localhost   database: tiendatech
        password: 12345678   port: 5432

Crear y cargar la base (todo en un solo archivo, se puede repetir)
   1. Crear la base:              CREATE DATABASE tiendatech;
   2. Cargar esquema + datos:     psql -U postgres -d tiendatech -f db/database.sql
   El archivo db/database.sql borra todo y lo vuelve a crear: esquema, triggers,
   datos de ejemplo y contrasenas ya encriptadas. Es seguro re-ejecutarlo.

Levantar el servidor
   - Dentro de la carpeta  tiendatech/  ejecutar:   npm install   (una vez)
   - Luego:   npm start
   - Al arrancar, la consola muestra DOS lineas:
        Kozmok escuchando en http://localhost:3000
        Base de datos: conectada (tiendatech@localhost:5432) - 20 productos
     Si en vez de "conectada" dice "SIN CONEXION" o "SIN TABLAS", revisa que
     PostgreSQL este encendido y que db.config.js sea correcto, o vuelve a
     cargar db/database.sql.

Direcciones
   - Tienda (clientes):     http://localhost:3000/
   - Panel interno:         http://localhost:3000/admin/login.html
     (no hay enlace desde la tienda; se entra por URL, a proposito)


===============================================================================
 2. ROLES, ACCESOS Y CUENTAS DE PRUEBA
===============================================================================

Todas las cuentas (cliente o internas) las puede dar de alta un ADMIN desde
   Panel -> "Cuentas y equipo" -> "Nueva cuenta"  (elige el Tipo).
El cliente además puede registrarse solo desde la tienda.

CLIENTE
   - Compra en la tienda. Solo ve y edita SUS datos, pedidos, carrito, puntos.
   - Nunca entra al panel interno.

ROLES INTERNOS (entran por /admin/login.html; el menu se adapta al rol)
   - ADMINISTRADOR : acceso total, incluida la gestion de cuentas y equipo.
   - VENDEDOR      : todo el CRM y la tienda; NO gestiona cuentas.
   - SOPORTE       : Dashboard, Clientes, Interacciones, Evaluaciones,
                     Soporte, Garantias, Reportes, Mi actividad, Config.
   - ALMACEN       : Dashboard, Pedidos, Inventario, Garantias, Analitica
                     chatbot, Mi actividad, Configuracion.
   El menu lateral solo muestra las secciones permitidas para ese rol, y si
   alguien abre por URL una seccion que no le toca, se le manda al Dashboard.

   Para AGREGAR un rol nuevo hay que tocar 3 lugares:
     1. db/database.sql        -> CHECK (rol IN (...)) de la tabla usuarios
     2. server.js              -> objeto ROLES_INTERNOS
     3. admin/js/admin-layout.js -> objeto PERMISOS (que secciones ve)

   Nota: ya no son "admin123"/"demo123" a proposito. Esos patrones estan
   en listas publicas de contrasenas filtradas, y el navegador (Chrome/
   Edge) muestra un aviso nativo de "esta contrasena fue expuesta,
   cambiala" al iniciar sesion con ellas. Ese aviso es del navegador, no
   de la pagina, asi que no se puede quitar ni re-vestir con el tema de
   Kozmok; la solucion real es no usar contrasenas de ese tipo.

Seguridad de sesion
   - El token de cliente y el token de admin se guardan por separado en el
     navegador y NUNCA se mezclan: la tienda usa el de cliente, /admin/* usa
     el de admin.
   - Si el token de admin vence o es invalido, cualquier pantalla del panel
     regresa sola a /admin/login.html.
   - "Cerrar sesion": en la tienda esta en el menu de la cuenta (arriba a la
     derecha); en el panel, al pie de la barra lateral.


===============================================================================
 3. LADO CLIENTE  -  LA TIENDA EN LINEA
===============================================================================

3.1  INICIO  (index.html)
   - Portada con el titulo grande, buscador y accesos.
   - Bloque "Explora": categorias, usos ("gaming", "oficina"...) y una banda
     que invita a preguntarle al asesor (chatbot) si no sabes que comprar.
   - "Como funciona": 3 pasos (explora / pregunta al asesor / compra y gana
     puntos).
   - "Destacados" y "Vistos recientemente".
   - Cuando la URL lleva un filtro (busqueda, categoria, uso, precio) la
     portada se convierte en CATALOGO: solo la lista de productos con filtros.

3.2  BUSCADOR Y NAVEGACION  (barra superior, en todas las paginas)
   - Campo de busqueda + selector de alcance ("Todo" o una categoria) +
     boton Buscar.
   - "Categorias" desplegable.
   - Iconos: favoritos, carrito (con contador) y el menu de la cuenta.
   - En movil hay un menu lateral y una barra inferior tipo app.

3.3  FICHA DE PRODUCTO  (ventana emergente desde el catalogo)
   - Fotos, especificaciones (procesador, RAM, grafica, pantalla), precio y
     stock real.
   - Selector de cantidad y aviso "Solo quedan N" cuando hay poco stock.
   - Boton "Agregar al carrito".
   - Resenas del producto: promedio de estrellas y comentarios. Si has
     iniciado sesion, puedes dejar o editar tu resena.
   - Boton "Comparar" (tambien en cada tarjeta del catalogo): ver 3.3b.
   - Si no hay imagen del producto se muestra una imagen generica; nunca
     aparece una imagen rota.

3.3b COMPARADOR DE PRODUCTOS
   - En cada tarjeta del catalogo y en la ficha hay un boton "Comparar".
   - Al marcar productos (hasta 4) aparece una barra fija abajo con los
     elegidos y un boton "Comparar".
   - "Comparar" abre  comparar.html?ids=...  con una tabla lado a lado:
     precio, marca, categoria, procesador, RAM, almacenamiento, grafica,
     pantalla, usos, disponibilidad y calificacion. Resalta en verde el
     mejor valor de cada fila (precio mas bajo, mas RAM, mas stock, etc.).
   - Desde ahi puedes agregar al carrito o quitar una columna.

3.3c GARANTIA EXTENDIDA
   - Al abrir un producto, ademas de la cantidad hay un selector de
     "Garantia extendida": Sin garantia / Basica 12 meses / Extendida 24
     meses / Total 36 meses. El costo es un % del precio del producto
     (6% / 12% / 18%) y se ve en la opcion.
   - Al agregar al carrito se guarda con esa linea. En el carrito cada
     producto tiene su propio selector para cambiar o quitar la garantia,
     y el resumen muestra una linea "Garantias extendidas".
   - Al comprar, por cada linea con garantia se genera un CERTIFICADO con
     folio (GAR-1000xx), un CODIGO para validarla, plazo (meses) y fechas
     de inicio / vencimiento. Aparece en el comprobante, en la pantalla de
     gracias y en "Mis garantias".
   - Si se cancela el pedido, sus garantias quedan "canceladas".

3.3d ARMA TU PC  (armar-pc.html, enlace "Arma tu PC" en Categorias y en inicio)
   - Arma un equipo de escritorio eligiendo cada pieza: placa base,
     procesador, memoria RAM, tarjeta grafica (opcional), almacenamiento,
     fuente de poder y gabinete.
   - Revisa la compatibilidad en vivo: socket procesador/placa, tipo de
     memoria (DDR4/DDR5), que el gabinete si acepte el tamano de la placa
     (ATX/MicroATX) y que la fuente alcance en watts para el procesador y
     la grafica elegidos. Cada regla se marca en verde o en rojo con el
     motivo exacto si hay un conflicto.
   - Boton "Recomendarme una build": eliges para que la vas a usar (gaming,
     oficina, diseno, etc.) y arma automaticamente una configuracion
     completa y compatible con esas piezas.
   - "Agregar todo al carrito" solo se habilita cuando no hay conflictos y
     estan elegidas las piezas obligatorias; agrega cada componente como
     un producto normal del carrito.

3.4  CHATBOT ASESOR  (boton flotante abajo a la derecha, en toda la tienda)
   - En la primera visita muestra una burbuja invitando a usarlo.
   - Puedes escribir con tus propias palabras lo que buscas (por ejemplo
     "una laptop para diseno con 20 mil pesos" o "algo para jugar barato")
     o usar las opciones rapidas. El asesor entiende del texto libre el
     uso, el presupuesto, la categoria y palabras clave (marca, tipo de
     producto), sin necesidad de contestar paso a paso.
   - Responde con recomendaciones concretas: solo productos que existen y
     que estan EN STOCK. Si nada calza perfecto, regresa lo mas cercano
     disponible en vez de dejarte sin respuesta.
   - Cada consulta queda registrada para que el equipo vea que pide la gente
     (ver 4.10).

   ARMAR POR PIEZAS DESDE EL CHAT
   - Despues de elegir para que la vas a usar, el asesor pregunta si
     quieres un equipo ya armado o armarlo tu mismo. Tambien puedes escribir
     directamente "quiero armar mi propia PC" o "elegir mis componentes".
   - Si armas por piezas: eliges tu presupuesto total y el asesor va
     recomendando una pieza a la vez (placa base, procesador, RAM, tarjeta
     grafica opcional, almacenamiento, fuente y gabinete), siempre
     filtrando solo lo que es COMPATIBLE con lo que ya elegiste (mismo
     socket, mismo tipo de RAM, gabinete que si acepte la placa, fuente con
     watts suficientes) y ordenado por tu area de uso y precio.
   - Cada sugerencia tiene su boton "Elegir y agregar": la agrega al
     carrito al instante y sigue con la siguiente pieza en el mismo chat,
     mostrando cuanto presupuesto te va quedando.
   - Al terminar todas las piezas, resume el total y te lleva al carrito.

3.5  CARRITO Y COMPRA  (carrito.html)
   - Para comprar hay que iniciar sesion (si no, te manda al login y vuelve).
   - Lista de productos con [-] cantidad [+], "Quitar" y "Vaciar carrito".
   - Barra de progreso de envio gratis (gratis desde $10,000; si no, $199).
   - Resumen: Subtotal, IVA 16%, Envio, Descuento por puntos, Total.
   - Usar puntos del Club: campo para canjear puntos en multiplos de 100
     (100 puntos = $10 de descuento). El total se recalcula al instante.
   - Direccion de envio: escribir una nueva o elegir una guardada.
   - Metodo de pago:
        * una de tus tarjetas guardadas,
        * "Usar otra tarjeta..." (pide numero, titular, MM/AA y CVV; puedes
          marcar "guardar esta tarjeta"),
        * Transferencia bancaria (SPEI),
        * Pago en tienda.
     Nota: es una demo, no se cobra nada real. Del numero de tarjeta solo se
     guardan la marca y los ultimos 4 digitos; el CVV nunca se guarda.
   - Al confirmar SIEMPRE se genera un COMPROBANTE (recibo.html), se guarda
     en la cuenta y lo puede ver el equipo. Segun el metodo:
        * Tarjeta  -> el pedido queda "Confirmado" y "Pagado"; los puntos se
                      acreditan al instante. El comprobante es el recibo de
                      compra con todos los datos.
        * SPEI     -> el pedido queda "Pago pendiente". El comprobante es una
                      FICHA DE PAGO con banco, beneficiario, CLABE, concepto/
                      referencia, monto exacto y fecha limite.
        * En tienda-> el pedido queda "Pago pendiente". La ficha de pago trae
                      un CODIGO y un QR para presentar en caja, mas el monto
                      y la fecha limite.
     En SPEI y tienda el stock se reserva, pero los puntos GANADOS solo se
     acreditan cuando el equipo registra el pago. Si se cancela el pedido se
     devuelven el stock y los puntos que se hubieran canjeado.
   - Boton "Ya realice el pago": el cliente avisa al equipo (no confirma el
     pago por si solo).

3.6  MI CUENTA  (menu arriba a la derecha -> "Perfil")
   Cada seccion es su propia pagina:

   Resumen (perfil.html)
      - Saludo, tarjeta virtual de socio (ver 7), nivel del Club con su
        insignia, numero de compras, total gastado, favoritos.
      - Ultimos 3 pedidos y accesos rapidos.

   Mis pedidos (pedidos.html)
      - Cada pedido muestra un RASTREO VISUAL de 4 etapas con iconos y fecha:
        Confirmado -> En preparacion -> Enviado -> Entregado. La etapa actual
        va resaltada y debajo hay una frase ("Tu pedido va en camino…",
        "Entregado. ¡Gracias!"). En pantallas chicas el rastreo se ve como
        linea de tiempo vertical.
      - Si el pago esta pendiente, en vez del rastreo sale un aviso ambar con
        la referencia y la instruccion; el rastreo arranca al confirmarse el
        pago. Si el pedido esta cancelado, sale un aviso rojo.
      - "Ver detalle" abre productos, importes y guia de envio.
      - "Comprobante" / "Ficha de pago" abre el recibo del pedido.
      - En pedidos con pago pendiente: boton "Ya realice el pago".
      - En pedidos entregados: "Dejar resena" para calificar cada producto.
   La pantalla de agradecimiento (gracias.html) tambien muestra un mini
   rastreo de las 4 etapas.

   Club de puntos (recompensas.html)
      - Saldo de puntos y su valor en dinero.
      - Nivel actual con insignia y barra de avance al siguiente nivel.
      - Tabla de los 4 niveles (Bronce, Plata, Oro, Platino) y sus reglas.
      - "Movimientos recientes": cada suma o resta de puntos.

   Favoritos (favoritos.html)
      - Productos guardados con el corazon; se pueden quitar o abrir.

   Mis resenas (resenas.html)
      - Todas las resenas que has dejado; se pueden editar o borrar.

   Mis garantias (garantias.html)
      - Certificados de garantia extendida de tus compras, con folio,
        codigo para validar, vigencia (inicio -> vence) y estado (Activa,
        Usada, Vencida, Cancelada).
      - "Usar la garantia": describes la falla y el equipo la revisa. Queda
        marcada "en revision" hasta que la resuelvan.

   Direcciones (direcciones.html)
      - Alta/edicion/borrado de direcciones; marcar una como predeterminada.

   Metodos de pago (pagos.html)
      - Tus tarjetas guardadas (marca, ultimos 4, titular, expiracion).
      - "Agregar tarjeta", "Hacer predeterminada", "Eliminar".
      - Recordatorio de que no se guarda el numero completo ni el CVV.

   Soporte (soporte.html)  -> ver seccion 9.

   Mis datos (datos.html)
      - Nombre, telefono, empresa, ciudad, estado. Se guardan en la base.

   Seguridad (seguridad.html)
      - Cambio de contrasena (pide la actual).

   Preferencias (preferencias.html)
      - Notificaciones por correo (boletin, ofertas, estado de pedidos,
        stock de favoritos).
      - Apariencia: elegir el tema de color (ver 10).

3.7  REGISTRO DE CUENTA  (registro.html)
   - Pide nombre, correo, contrasena y CONFIRMAR contrasena (deben coincidir).
   - Muestra un medidor de seguridad de la contrasena:
        Muy debil / Debil (rojo) -> Regular (naranja) -> Buena -> Fuerte (verde).
     Se calcula por longitud y por mezcla de mayusculas, minusculas, numeros y
     simbolos. El minimo para registrarse son 6 caracteres.
   - Al crear la cuenta se genera automaticamente el codigo de socio para la
     tarjeta virtual (ver 7).

3.8  MENSAJES EN PANTALLA
   - La tienda no usa ventanas del navegador. Todo aviso sale como un "toast"
     discreto (arriba) o como una ventana propia de confirmacion.


===============================================================================
 4. LADO ADMIN  -  PANEL CRM  (http://localhost:3000/admin/login.html)
===============================================================================

La barra lateral esta agrupada en tres bloques: CRM, SCM y CUENTA. El
bloque CRM cubre clientes, ventas y relacion con el cliente; el bloque
SCM cubre la cadena de suministro (inventario, proveedores, logistica).

CRM y SCM son desplegables: el titulo del bloque es un enlace directo a
su pantalla principal y la flechita junto al titulo solo muestra u oculta
sus opciones sin salir de donde estas. El bloque del modulo en el que
estas se abre solo; el otro queda cerrado, para que la lista no se sienta
larga. El bloque CUENTA no es desplegable, siempre esta a la vista.

Ambos bloques empiezan con su propio "Dashboard" (el de CRM en
admin/dashboard.html, el de SCM en admin/scm.html -- este ultimo tambien
se le llama "Panel SCM" en su encabezado). Los dos tienen arriba un menu
de accesos directos con iconos grandes a cada seccion de su modulo
(excepto a si mismos), para navegar sin tener que usar la barra lateral.

Cada pantalla tiene un encabezado con titulo y, si aplica, un boton de accion.

4.1  DASHBOARD  (admin/dashboard.html)  [bloque CRM]
   - Indicadores: total de clientes, clientes activos, interacciones del mes,
     tickets de soporte activos, productos con stock critico.
   - Grafica de clientes por etapa del CRM (dona).
   - Grafica de interacciones por tipo (barras).
   - Tabla "Clientes en riesgo": mas de 30 dias sin contacto registrado.
   - Tabla "Productos mas vendidos".

4.2  CLIENTES  (admin/clientes.html)  [CRM]
   - Listado con buscador (nombre, correo, empresa) y filtro por etapa.
   - Columnas: ID, nombre, correo, empresa, etapa CRM, estado.
   - "Nuevo cliente": crea la cuenta (contrasena editable, temporal por
     defecto) y abre su ficha.
   - "Exportar CSV": descarga el listado tal como esta filtrado.
   - Clic en una fila o en "Ver ficha" -> ficha del cliente.

4.3  FICHA DE CLIENTE  (admin/cliente.html?id=...)  [CRM]
   Es la pantalla central del CRM (equivale al "Detalle de cliente").
   - Cabecera: nombre, etiqueta de etapa, estado, correo y empresa.
   - Botones: "Editar cliente", "Cambiar etapa", "Nueva interaccion".
   - Tarjetas: Compras, Valor total, Interacciones, Club (nivel con insignia
     y puntos).
   - Pestanas:
        Informacion  : telefono, empresa, ciudad, registro, ultimo acceso,
                       etapa CRM, estado, Club de puntos, codigo de socio.
        Pedidos      : historial de compras del cliente (orden, fecha,
                       productos, total, estado) con "Detalle" expandible.
        Interacciones: linea de tiempo de todas las interacciones del cliente
                       (llamada, correo, reunion, chat, soporte).
        Evaluaciones : resenas que el cliente ha dejado en productos.
   - "Cambiar etapa": Prospecto -> Activo -> Frecuente -> Inactivo. El paso a
     "Activo" tambien ocurre solo al confirmarse la primera compra.
   - "Nueva interaccion": abre el SIMULADOR (ver 4.4); queda ligada al
     usuario interno que la registro.

4.4  INTERACCIONES  (admin/interacciones.html)  [CRM]
   - Todas las interacciones de todos los clientes, con filtros por texto,
     tipo y rango de fechas. La columna "Registro" dice quien la capturo.
   - "Nueva interaccion" abre un SIMULADOR con 5 modos; cada uno arma la
     descripcion que se guarda:
        Llamada : muestra el telefono, boton "Iniciar llamada" -> "Llamando"
                  -> cronometro -> "Colgar"; luego eliges el resultado
                  (Contesto / No contesto / Buzon) y agregas notas.
        Correo  : "Para" con el correo del cliente, plantillas (seguimiento,
                  cotizacion, bienvenida, recordatorio de pago), asunto y
                  cuerpo. "Enviar correo" (simulado).
        Reunion : fecha, hora, modalidad (videollamada/presencial/telefono)
                  y agenda. "Agendar reunion".
        Chat    : mini conversacion con respuestas rapidas; "Cerrar chat".
        Soporte : prioridad + nota; enlace al gestor de tickets para
                  seguimiento formal con folio.
   - En la ficha de un cliente el simulador ya viene con ese cliente fijo.

4.5  EVALUACIONES  (admin/evaluaciones.html)  [CRM]
   - Todas las resenas de productos hechas por clientes.
   - Indicadores: total, promedio de estrellas, resenas criticas (<= 2).
   - Filtro por calificacion (5, 4+, 3+, criticas).

4.6  SOPORTE  (admin/soporte.html)  [CRM]  -> ver seccion 9
   - Cola de tickets con contadores (Abiertos, En proceso, Resueltos,
     Cerrados) y filtros por estado y prioridad.
   - Al abrir un ticket: hilo de mensajes, selector de estado y prioridad,
     y campo para responder al cliente.

4.6b GARANTIAS  (admin/garantias.html)  [CRM]
   - "Validar garantia": escribe el codigo que trae el cliente y muestra si
     esta VALIDA (verde) o no (roja), con producto, cliente, vigencia y
     dias restantes.
   - Indicadores: activas, con reclamo, usadas, vencidas/canceladas.
   - Tabla de todas las garantias con filtro por estado y busqueda (folio,
     codigo, cliente, producto, pedido). Las que tienen un reclamo del
     cliente llevan una etiqueta "reclamo".
   - Al abrir una: "Marcar como usada" (pide una nota de resolucion),
     "Cerrar reclamo sin usar" o "Marcar vencida".

4.7  REPORTES  (admin/reportes.html)  [CRM]
   - Rango de fechas ("Del ... al ...") o "Todo el historico".
   - KPIs: clientes totales, activos, interacciones del periodo, clientes sin
     interaccion (30+ dias), nuevos clientes del periodo, ventas del periodo.
   - Graficas: interacciones por tipo y clientes por etapa.
   - "Exportar CSV": descarga todos los indicadores del periodo.

4.8  PEDIDOS  (admin/pedidos.html)  [CRM]
   - Listado con filtro por estado. Cada fila muestra el estado y el pago
     como pildoras de color. Clic en la fila o en "Gestionar" abre el panel.
   - Panel de gestion:
        * PIPELINE visual de 5 pasos (Pendiente -> Confirmado -> Procesando
          -> Enviado -> Entregado). Haz clic en un paso para mover el pedido
          ahi (te pide confirmar si es un retroceso). "Cancelar pedido"
          aparte.
        * Bloque de PAGO: si esta pendiente, muestra el metodo y la
          referencia y un boton grande "Marcar pago recibido" -> pasa a
          "Confirmado", otorga los puntos y actualiza las metricas del
          cliente. Si el cliente pulso "Ya realice el pago", lo indica.
        * Productos, totales y "Ver comprobante".
   - "Exportar CSV": descarga los pedidos tal como estan filtrados.
   - Enlace directo:  /admin/pedidos.html?open=<id>  abre ese panel.

4.9  INVENTARIO  (admin/productos.html)  [SCM]
   - Catalogo completo: ID, producto, categoria, proveedor, precio, stock,
     estado.
   - "Nuevo producto" y edicion: datos, especificaciones tecnicas, precio,
     stock, stock minimo, imagen (URL opcional; si se deja vacia se usa la
     generica), proveedor y metodo de reabastecimiento (push = se repone
     por calendario; pull = se repone cuando baja el stock).
   - Reabastecer stock desde la ficha del producto o desde el boton
     "Restock" de la tabla.
   - Alerta de stock critico: en cuanto un producto llega a su stock
     minimo o por debajo, aparece arriba de la tabla con su proveedor,
     metodo de reabastecimiento y un boton directo para reabastecerlo.
   - Logistica por categoria: panel con una barra por categoria que
     muestra cuantos productos se reabastecen push vs. pull, para ver
     de un vistazo la estrategia de cada linea de catalogo.
   - Filtro "Reabastecimiento" (Todos/Push/Pull) arriba de la tabla,
     para ver solo los productos de un metodo u otro.

4.9b PROVEEDORES  (admin/proveedores.html)  [SCM]
   - Lista de proveedores con contacto, telefono, correo, cuantos
     productos activos abastece cada uno y su estado.
   - Tiempo de entrega (dias): base de la estrategia de reabastecimiento
     (a mayor tiempo de entrega, antes hay que reordenar). Se muestra en
     verde (5 dias o menos), ambar (6-9) o rojo (10 o mas).
   - "Nuevo proveedor" y edicion: nombre, contacto, telefono, correo,
     tiempo de entrega y activo/inactivo.
   - "Eliminar": si el proveedor ya tiene productos asociados se
     desactiva en lugar de borrarse (para no perder el historial).
   - La alerta de stock critico en Inventario (4.9) muestra el tiempo de
     entrega del proveedor de cada producto, para decidir que tan urgente
     es reordenar.

4.9c MOVIMIENTOS DE INVENTARIO  (admin/movimientos.html)  [SCM]
   - Historial de entradas y salidas de stock: fecha, producto, tipo
     (entrada/salida), cantidad, motivo y que usuario lo genero.
   - Se registra solo: cada venta (salida), cancelacion de un cliente
     (entrada), restock manual (entrada) y recepcion de una orden de
     compra (entrada).
   - "Nuevo movimiento": registra a mano una entrada o salida de stock
     (merma, conteo fisico, ajuste de inventario, etc.) con su motivo.
     Una salida no puede ser mayor al stock actual. Si una salida manual
     deja al producto en stock critico, tambien se le genera sola la
     orden de compra (ver 4.9d).
   - Filtros por tipo y por nombre de producto.

4.9d ORDENES DE COMPRA  (admin/ordenes-compra.html)  [SCM]
   - El otro lado de la cadena de suministro: pedidos de reposicion
     HACIA los proveedores (distinto de los "Pedidos" de venta a
     clientes). Folio (OC-100x), producto, proveedor, cantidad, estado y
     fecha.
   - "Nueva orden": eliges el producto (sugiere una cantidad segun su
     stock minimo), el proveedor (por default el que ya tiene asignado
     el producto) y notas opcionales.
   - Estados: Pendiente -> En proceso -> Recibido (al marcarla recibida,
     el stock del producto sube solo y queda registrado el movimiento de
     inventario correspondiente) o Cancelado en cualquier momento antes
     de recibirla.
   - Acceso directo: el boton "Generar orden" en la alerta de stock
     critico de Inventario (4.9) abre una orden nueva ya con ese producto
     elegido.
   - AUTOMATICA: en cuanto un producto con proveedor asignado cae en (o
     sigue en) stock critico -- por una venta, por editar el stock a mano,
     o porque lo recibido en una orden no alcanzo -- se genera una orden
     de compra sola, sin que nadie tenga que darle clic a nada. Se marca
     en sus notas como "Generada automaticamente". Si el producto ya tiene
     una orden pendiente o en proceso, no se genera otra; en Inventario,
     la alerta de stock critico muestra "OC-100x en curso" en lugar del
     boton "Generar orden" mientras eso sea cierto.

4.9e LOGISTICA  (admin/logistica.html)  [SCM]
   - Configurar estrategia: eliges un producto y dos tarjetas grandes
     (Push / Pull) explican cada una y marcan cual esta activa. "Guardar
     estrategia" actualiza el metodo de reabastecimiento de ese producto
     (lo mismo que el campo de Inventario, pero en su propia pantalla).
   - Comparativa push vs. pull: dos tarjetas con el total de productos en
     cada estrategia (de todo el catalogo activo) y una tabla completa
     con filtro por categoria y por estrategia.

4.9f PANEL SCM  (admin/scm.html)  [SCM]
   - En la barra lateral aparece como "Dashboard" (primer elemento del
     bloque SCM, igual que el Dashboard es el primero del bloque CRM).
   - Metricas: productos activos, proveedores, ordenes de compra
     abiertas, productos en stock bajo y rotacion de inventario (%
     de unidades vendidas contra el stock actual).
   - Nivel de madurez SCM: Inicial / En desarrollo / Optimizado, calculado
     de datos reales del sistema (no es una lista que se marca a mano):
     que haya productos con proveedor asignado, movimientos de inventario
     registrados, estrategia push Y pull en uso (no solo una), ordenes de
     compra generadas y reportes con ventas reales. El nivel sube solo
     conforme el equipo usa cada parte del modulo.
   - "Que significa este nivel": explica en texto que falta o que ya se
     logro para el nivel actual.
   - Cada punto del checklist es un enlace: si esta pendiente, lleva
     directo a la pantalla donde resolverlo (Inventario, Movimientos,
     Logistica, Ordenes de compra o Reportes); si ya esta cumplido, lleva
     a revisarlo igual.

4.9g REPORTES SCM  (admin/reportes-scm.html)  [SCM]
   - Mismas metricas generales que el Dashboard de SCM (productos,
     proveedores, ordenes abiertas, stock bajo, rotacion).
   - Productos mas vendidos: grafica de barras con unidades vendidas.
   - Estrategia de reabastecimiento, con dos selectores independientes:
        * Que estadistica ver: Cantidad de productos o Valor de
          inventario (stock x precio) de cada estrategia.
        * Como verla: Grafica (barras) o Tabla exacta (numero de
          productos, % del catalogo, valor en pesos y % del valor, para
          push y pull) -- para no depender solo de lo visual cuando se
          necesita el dato preciso.
   - Inventario critico: tabla de solo lectura (producto, stock actual,
     stock minimo, proveedor) de los productos en su minimo o por debajo.

4.10 ANALITICA CHATBOT  (admin/chatbot.html)  [CRM]
   - Que esta buscando la gente en el asesor: por uso, por rango de
     presupuesto y ultimas consultas.
   - Una consulta sin sugerencias es una oportunidad de reabastecer o de
     ampliar catalogo.

4.11 MI ACTIVIDAD  (admin/mi-actividad.html)  [CUENTA]
   - Interacciones que TU (el usuario interno con la sesion activa) has
     registrado.

4.12 CUENTAS Y EQUIPO  (admin/usuarios.html)  [CUENTA]  -- solo ADMIN
   - Tabla con el personal interno (administradores, vendedores, soporte,
     almacen) y su estado.
   - "Nueva cuenta": primero eliges el TIPO y el formulario se adapta:
        * Cliente          -> nombre, correo, contrasena, telefono, empresa,
                              ciudad, estado. Se crea con su codigo de socio
                              y aparece en la seccion Clientes (no en esta
                              tabla). Ofrece abrir su ficha al terminar.
        * Rol interno       -> nombre, email, contrasena, telefono. El rol es
          (Admin/Vendedor/    el tipo elegido.
           Soporte/Almacen)
   - Tambien puedes crear un cliente desde Clientes -> "Nuevo cliente".
   - A los roles que no son admin, esta seccion no les aparece en el menu.

4.13 CONFIGURACION  (admin/configuracion.html)  [CUENTA]
   - Apariencia: elegir el tema de color de toda la plataforma.
   - Etapas del CRM: recordatorio del embudo Prospecto/Activo/Frecuente/
     Inactivo.
   - Club de puntos: recordatorio de las reglas.
   - Acerca de: version y stack.


===============================================================================
 5. ROLES INTERNOS  -  QUE VE Y HACE CADA UNO
===============================================================================

Todos entran por /admin/login.html. El menu lateral se arma segun el rol.

VENDEDOR
   Ve todo menos "Cuentas y equipo". Flujo tipico:
   1. Dashboard: clientes en riesgo y tickets activos.
   2. Clientes: buscar al cliente y abrir su ficha.
   3. Registrar la interaccion (llamada/correo/reunion) con lo acordado.
   4. Atender tickets en Soporte si hay una queja formal.
   5. Actualizar el estado del pedido en Pedidos cuando avance el envio.
   6. Ajustar stock en Inventario si se recibe mercancia.

SOPORTE
   Ve: Dashboard, Clientes, Interacciones, Evaluaciones, Soporte, Reportes,
   Mi actividad, Configuracion. No ve Pedidos, Inventario ni Cuentas.
   Flujo tipico: revisar la cola de tickets, responder al cliente, cambiar
   estado/prioridad, y dejar registrada la interaccion en la ficha.

ALMACEN
   Ve: Dashboard (CRM), Pedidos, Analitica chatbot -- y en el bloque SCM:
   Dashboard (Panel SCM), Inventario, Proveedores, Movimientos, Ordenes de
   compra, Logistica, Reportes -- ademas de Mi actividad y Configuracion. No ve
   Clientes, Interacciones, Soporte ni Cuentas.
   Flujo tipico: procesar pedidos (confirmado -> procesando -> enviado ->
   entregado), vigilar el stock critico, generar una orden de compra al
   proveedor cuando haga falta, marcarla recibida cuando llegue (el stock
   sube solo) y revisar el Dashboard de SCM para ver el nivel de madurez y
   las metricas generales.

ADMINISTRADOR
   Ve todo, incluido "Cuentas y equipo" (alta de cuentas y roles).


===============================================================================
 6. CLUB DE PUNTOS  (sistema de recompensas)
===============================================================================

Valor
   - 100 puntos = $10 de descuento (1 punto = $0.10).
   - Se canjean SOLO en multiplos de 100, en el carrito, y nunca dejan el
     subtotal en negativo.

Como se ganan
   - Al confirmar un pedido:  puntos = (subtotal / 20) * multiplicador del nivel
     redondeado hacia abajo.

Niveles (insignia de escudo con color propio y 1 a 4 puntos)
   - Bronce  x1     desde $0         o  0 compras
   - Plata   x1.15  desde $15,000    o  2 compras
   - Oro     x1.3   desde $50,000    o  5 compras
   - Platino x1.6   desde $120,000   o  10 compras
   El nivel es el MAYOR entre el que dan las compras totales ($) y el que da
   la frecuencia (numero de compras). Sube solo; no baja por inactividad.

Donde se ve el nivel
   - Tarjeta de socio y tarjeta "Nivel del Club" en Resumen.
   - Pagina Club de puntos (barra de avance + tabla de niveles).
   - Ficha del cliente en el panel (tarjeta "Club" y pestana Informacion).
   - Pantalla de verificacion de socio (ver 7).

Movimientos
   - Cada compra (puntos ganados) y cada canje (puntos restados) se registran
     con fecha, concepto y el pedido asociado. Se ven en "Movimientos
     recientes".


===============================================================================
 7. TARJETA VIRTUAL Y QR DE SOCIO
===============================================================================

Cada cliente tiene una tarjeta virtual en su Resumen (perfil.html) con:
   - un numero de tarjeta (derivado de su ID, siempre el mismo),
   - su nivel del Club con insignia,
   - titular, socio desde, puntos y total de compras,
   - un CODIGO QR y su codigo de socio en texto (formato  TTMX-XXXXXX ).

Codigo de socio
   - Se genera automaticamente al registrarse. Cuentas antiguas reciben uno
     la primera vez que abren su Resumen.

Uso en tienda fisica
   - El QR apunta a:   http://<servidor>/socio.html?c=<codigo>
   - Al escanearlo se abre "Verificacion de socio": una pantalla limpia para
     el personal de tienda que muestra nombre, nivel, puntos disponibles,
     su valor en dinero, socio desde y el codigo. Termina con "Socio
     verificado".
   - Esa pantalla es publica pero NO expone datos sensibles (ni correo, ni
     telefono, ni pedidos).
   - Endpoint que la alimenta:  GET /api/socio/:codigo


===============================================================================
 8. METODOS DE PAGO
===============================================================================

Donde
   - Cuenta -> "Metodos de pago" (pagos.html) para administrarlos.
   - Tambien se puede agregar una tarjeta durante la compra, en el carrito.

Que se guarda
   - Tipo (tarjeta / transferencia / efectivo), marca (Visa, Mastercard,
     American Express u "otra"), ultimos 4 digitos, titular y expiracion.
   - NUNCA se guarda el numero completo ni el CVV. El CVV se pide y se valida
     en el navegador, pero no se envia al servidor.

Marca automatica
   - Se deduce del numero:  empieza en 4 -> Visa;  51-55 o 22-27 -> Mastercard;
     34 o 37 -> American Express;  cualquier otro -> "otra".

En el pedido
   - El pedido guarda un texto legible del metodo, por ejemplo
     "Tarjeta Visa ****4821", "Transferencia SPEI" o "Pago en tienda".

Aviso
   - Es una demo educativa: no hay pasarela de pago ni cargos reales.


===============================================================================
 9. TICKETS DE SOPORTE  (cliente <-> equipo)
===============================================================================

Lado cliente  (soporte.html, dentro de Mi cuenta)
   - "Nuevo ticket": asunto, categoria, prioridad y descripcion.
   - Cada ticket recibe un folio  TK-1001, TK-1002, ...
   - Al abrir un ticket se ve el hilo de mensajes y un campo para responder.
   - Si el ticket estaba "Resuelto" o "Cerrado" y el cliente escribe de
     nuevo, se REABRE automaticamente.
   - Desde el Centro de ayuda (ayuda.html) el boton de contacto lleva aqui
     (o al login si no hay sesion).

Lado equipo  (admin/soporte.html)
   - Cola con contadores por estado y filtros por estado y prioridad.
   - Al abrir un ticket: hilo completo, y selectores para cambiar ESTADO
     (Abierto, En proceso, Resuelto, Cerrado) y PRIORIDAD (Baja, Media, Alta).
   - "Enviar respuesta" agrega un mensaje del equipo; si el ticket estaba
     "Abierto" pasa a "En proceso".

Relacion con el CRM
   - Cada ticket nuevo tambien se registra como interaccion de tipo
     "soporte" en la ficha del cliente, para tener la historia completa en
     un solo lugar.

 11. PREGUNTAS FRECUENTES / SOLUCION DE PROBLEMAS
===============================================================================

P: Al cargar db/database.sql salen muchos "NOTICE: ... does not exist,
   skipping". Esta mal?
R: No. El archivo empieza borrando tablas que en una base nueva todavia no
   existen; PostgreSQL solo avisa que las salta. Si no hay lineas "ERROR",
   la carga fue correcta. Verifica con:  SELECT COUNT(*) FROM productos;  (=20)

P: npm start no dice nada sobre la base.
R: Ahora si: la segunda linea de la consola indica "conectada" o el problema.
   Si dice "SIN CONEXION", enciende PostgreSQL o corrige db.config.js.
   Si dice "SIN TABLAS", vuelve a cargar db/database.sql.

P: Inicio sesion (o creo cuenta) y me regresa al login una y otra vez.
R: Era un error ya corregido: el token de admin viejo se enviaba tambien en
   la tienda. Solucion para el usuario: recarga dura del navegador
   (Ctrl+Shift+R). Si persiste, en DevTools -> Application -> Local Storage,
   borra la clave "tt_admin_token".

P: Las imagenes de producto no cargan / salen errores en la consola del
   navegador.
R: El catalogo ya no depende de imagenes externas. Si un producto no tiene
   imagen se muestra una generica. Para poner imagenes reales, edita el
   producto en el panel (Inventario) y pega una URL en el campo "Imagen".

P: No puedo comprar, me pide iniciar sesion.
R: Es correcto: la compra requiere una cuenta de cliente. Tras iniciar
   sesion vuelve solo al carrito.

P: Un cliente no puede entrar al panel.
R: Es correcto. El panel solo acepta usuarios internos
   (admin/vendedor/soporte/almacen).

P: Como doy de alta una cuenta nueva (cliente o de personal)?
R: Con una cuenta de admin: panel -> "Cuentas y equipo" -> "Nueva cuenta".
   Elige el Tipo (Cliente o un rol interno), llena los campos, define una
   contrasena y comunicasela. Un cliente tambien puede registrarse solo
   desde la tienda.

P: Necesito un rol distinto a los que hay.
R: Se agrega en 3 lugares: el CHECK de la tabla usuarios (db/database.sql),
   el objeto ROLES_INTERNOS en server.js y el objeto PERMISOS en
   admin/js/admin-layout.js (para decir que secciones ve). Recarga
   database.sql y reinicia.

P: Como reinicio los datos de ejemplo?
R: Vuelve a ejecutar  psql -U postgres -d tiendatech -f db/database.sql .
   Borra y recrea todo. (Cierra antes cualquier conexion abierta a la base,
   como pgAdmin, o te dira que esta en uso.)

Autenticacion
   - Cliente: token base64  cliente:<id>:<timestamp>  (localStorage tt_token).
   - Interno: token base64  usuario:<id>:<timestamp>   (localStorage
     tt_admin_token). El panel valida la sesion contra GET /api/admin/whoami.
   - Middleware: requireCliente + mismoCliente en /api/clientes/:id ;
     requireUsuario (+ requireAdmin) en /api/admin/... .

Endpoints utiles
   POST /api/auth/registro-cliente        alta de cliente (+ codigo de socio)
   POST /api/auth/login-cliente           login tienda   (campo "correo")
   POST /api/auth/login-usuario           login panel    (campo "email")
   GET  /api/admin/whoami                 valida sesion interna
   GET  /api/clientes/:id/recompensas     estado del Club (puntos, nivel...)
   GET  /api/clientes/:id/metodos-pago    tarjetas guardadas
   GET  /api/clientes/:id/tickets         tickets del cliente
   GET  /api/socio/:codigo                verificacion publica de socio (QR)
   GET  /api/admin/dashboard              KPIs del panel
   GET  /api/admin/reportes?desde=&hasta= reportes por rango de fechas

Reglas de negocio embebidas
   - IVA 16%. Envio $199, gratis desde $10,000 de subtotal.
   - Club: 100 puntos = $10; ganar = floor(subtotal/20 * multiplicador).
   - Etapa "Activo" automatica al confirmarse la primera compra.
   - Folio de ticket: TK-(1000 + id).
